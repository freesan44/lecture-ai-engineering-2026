# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：「3レベル＝受講生のスキルや難易度に合わせた3段階（レベル1基礎・入門／レベル2応用・実践／レベル3発展・挑戦）」という一般論を返した。「と推測されます」「場合がほとんどです」など推測を示す言い回しで、講座固有の具体的な定義には言及しなかった。
- 用語集の正しい意味と比べて気づいたこと：モデルは3段階の難易度という大枠は当てていたが、「実装＝自分でコードを書く」「発展＝調査や試行」という実際の定義とはズレており、「どれか1つで完了」「採点しない」という重要ルールには触れられなかった。講座固有の情報は学習していないため、もっともらしい一般論で補うしかない＝ハルシネーションの実例だと分かった。
- 表示できたトークン数（入力 / 出力）：入力 7 / 出力 531〜785（「LoRAとは何ですか？」を3回実行した際の値。

## 宿題

- 取り組んだレベル：発展
- やったこと：同じモデル（gemini-3.5-flash-lite）で3つの異なる質問（「LoRAとは何ですか？」「Transformerとは何ですか？」「RAGとは何ですか？」）を実行し、応答時間・トークン数・回答内容を計測・比較した。また、比較のため gemini-3.6-flash と gemini-3.8-flash にも同じ質問を送信した。さらに、app/ask.py を改修して会話履歴を保持し、応答時間の表示を追加した。
- 結果：
①同一質問の3回実行（LoRA）では、応答時間が 21.19 秒／22.09 秒／7.06 秒、出力トークン数が 785／664／531 と大きく変動した（入力は毎回 7 で固定）。回答内容の大筋（LoRAはLow-Rank Adaptation、PEFTの一種で少数のパラメータだけ学習する、など）は共通していたが、説明の詳しさ・具体例・構成が実行ごとに異なった。
②異なる質問では、Transformer が 26.53 秒・出力 609、RAG が 14.99 秒・出力 605 で、同じモデルでも質問によって応答時間が大きく異なることが分かった。
③gemini-3.6-flash と gemini-3.8-flash への同じ質問は、いずれも「モデルが混み合っています（503）」というエラーで失敗した。
④会話履歴を保持した状態で続けて質問できることを確認した（1回目の質問の内容を踏まえた回答が返ってくる）。
- 気づき・疑問：
①同じモデル・同じプロンプトでも出力トークン数が 531〜785（約1.5倍）まで変動し、LLMの生成が確率的であること、「1回正解したから大丈夫」とは言えないことを実感した。
②応答時間も同一質問で 7〜22 秒、異なる質問で 15〜27 秒と大きく変動し、サービス側の負荷や質問の内容にも依存することが分かった。
③上位モデル（3.6／3.8）は503が返り、無料枠のレート制限・混雑を実感した。強いモデルほど無料では使いにくいという「コストと効果のトレードオフ」の実例でもある。
④会話履歴を保持する＝過去のやり取りをプロンプトに含めて再送していることだと理解した。履歴が長くなるとトークン数が増え、コストと応答時間に影響しそうなので、履歴の長さの上限をどう設計すべきかが疑問に残った。
