# 第2回 演习与作业：使用 LoRA 学习回答格式，比较训练前后的表现

本回使用 Google Colab（T4 GPU，免费额度）进行，不使用 Codespaces。

## 本回目标

- 使用低秩适应（Low-Rank Adaptation，LoRA）对小模型进行短时间训练，通过数值和输出确认训练前后**哪些发生了变化，哪些没有变化**。
- 根据自己的实验结果，解释“模型可以通过训练学会格式，但不能保证它能判断自己不知道的事情，例如应该请求确认还是作出断言”。
- 用自己的话解释微调（Fine-Tuning）适合和不适合的场景。

## 使用的笔记本

- [notebooks/lora_format_tuning.ipynb](../../notebooks/lora_format_tuning.ipynb)
- 在 Colab 中打开：https://colab.research.google.com/github/matsuolab/lecture-ai-engineering-2026/blob/main/notebooks/lora_format_tuning.ipynb

以虚构课程的常见问题解答（FAQ，5个项目）为题材，使用 LoRA 对 `Qwen/Qwen3.5-0.8B` 训练20个轮次（14条训练数据重复20遍，共40步；使用T4约需4～5分钟）。

期望输出是一行 `{"answer": ..., "needs_review": ...}` 格式的 JSON。对于 FAQ 中没有答案的问题，正确做法是将 `needs_review` 设为 `true`，并回答“需要确认”。

评价分为两项：**格式遵守率**（是否遵守 JSON 格式）和**内容正确率**（`needs_review` 以及回答中的词句是否与标准答案一致）。

## 课前准备（可选，5分钟）

课前执行笔记本第0～3节，确认能够分配 GPU、安装软件库和下载模型，可以减少上课时遇到的问题。

Colab 会话断开后变量会消失，因此上课当天需要重新从第0节开始执行。

## 演习（30分钟）

1. 在 Colab 中打开笔记本，选择**文件 → 在云端硬盘中保存一份副本**，创建自己的副本。
2. 选择**运行时 → 更改运行时类型 → T4 GPU**。
3. 从上到下执行第0～3节（约5分钟）。阅读训练前的表格，确认**缺少哪些键**，以及回答内容是否与 FAQ 一致。
4. 在第4节进行训练（4～5分钟）。等待期间阅读“LoRA 与 QLoRA 的区别”，并观察 `trainable%` 和 `Training Loss` 的变化。
5. 在第5～6节评价训练后的模型，并与训练前比较。
   - 比较表：`format_rate` 和 `content_rate` 发生了怎样的变化。
   - `退行`：训练前通过、训练后却失败的问题；理想情况下列表为空。
   - 剩余失败类型：对于 FAQ 中没有答案的问题，是否套用其他条目并作出**断言**；对于 FAQ 中有答案的问题，是否以“没有记载”为由**回避回答**。
   - 第6节：面对 FAQ 和训练数据都没有涉及的问题，是请求确认，还是作出断言。
6. 在第7节生成 `result.json`。将要点写入 `lectures/02/answer.md`，并从作业分支 `lec02` 向自己派生仓库（fork）的 `main` 分支创建拉取请求（Pull Request，PR）；也可以直接在 GitHub 页面编辑 `answer.md`。可以将 `result.json` 放在 `lectures/02/` 下并包含在 PR 中。
7. 选择**运行时 → 断开并删除运行时**。

> Colab 的 GPU 免费使用时间有限。结束后务必删除运行时。
> 如果无法分配 GPU，或无法在规定时间内完成训练，请按照笔记本第4b节，参考讲师使用T4运行的结果进行比较和分析。提交时将 `executed_training_myself` 设为 `False`，并在 `answer.md` 中写明自己实际完成的范围。

即使固定随机种子（seed），GPU 上的训练也无法完全复现。与其他人相比，“剩余失败的问题”不同并不一定异常，请按失败类型比较。

## 作业（完成其中一个级别即可）

| 级别  | 内容                                                                                                                                                                                    |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 基础  | 从 `CONFIG` 的 `lora_r`、`lr`、`num_train_epochs` 中选择**一个**修改后重新训练，将 `format_rate`、`content_rate`、最终损失（loss）和训练时间与原设置并排记录。修改后选择**运行时 → 重新启动会话**，再从头执行（因为内存中仍保留训练后的模型）。比较两份 `result.json`。 |
| 实现  | 将 `FAQ`、`GROUNDED`、`UNGROUNDED` 替换为自己选择的题材（约5个项目），进行训练并比较训练前后。保持 JSON 格式和 `needs_review` 的设计不变。还需说明如何准备“没有依据”的问题。                                                                     |
| 拓展  | 使用 `scripts/make_sft_dataset.py` 从课程词汇表生成问答数据（`messages` 格式的 JSONL），代替 FAQ 用于训练。自行准备评价问题（词汇表中有的术语、改变说法的问题、词汇表中没有的术语）及标准答案，比较训练前后。再与检索词汇表的方法比较，分析训练模型的优缺点。                             |

拓展级的数据生成方式（在 Codespaces 中执行，然后将生成的文件上传到 Colab）：

```bash
uv run python scripts/make_sft_dataset.py > glossary_sft.jsonl
```

在 Colab 中，每一行都与笔记本的 `to_chat` 使用相同的 `messages` 格式，因此可以将读取后的各行直接传给 `Dataset.from_list`，再使用第4节的 `SFTTrainer` 进行训练。评价数据（`test` 和 `gold`）请根据词汇表自行重新制作。

第8节（以4位精度加载并比较输出）是无需训练的观察，任何级别都可以将其结果作为补充。保持4位精度进行训练的方法（QLoRA）尚未在本课程的 T4 环境中确认可运行，因此不属于作业范围。

## 注意事项

- 训练后，适配器（adapter）也会插入变量 `model` 所指向的模型中。如果要重新取得训练前的输出，请使用 `tuned.disable_adapter()`（参见第6节），或者重新启动会话。
- 笔记本的软件库固定为已经验证的版本（第0节的 `PINS`）。更改版本后可能无法正常运行。
